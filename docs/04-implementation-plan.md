# Implementation plan

Phased, with explicit checkpoints between phases so each can be
validated independently before the next is written.

## Proposed Go module layout

```

├── api/

│   ├── format/

│   │   ├── m4b.go               # tries /packaged_m4b
```

Public packages: none — this is an end-user CLI, not a library.

### ABS client: OpenAPI-driven, generated

The ABS HTTP client is **not hand-written**. The file
[`api/audiobookshelf.openapi.yaml`](../api/audiobookshelf.openapi.yaml)
is the contract — it defines exactly the subset of audiobookshelf
endpoints this project depends on, with their request/response schemas
and the `bearerAuth` security scheme.

At build time:

```go
// internal/abs/generate.go
package abs

//go:generate go tool oapi-codegen -config ../../api/oapi-codegen.yaml -o gen.go ../../api/audiobookshelf.openapi.yaml
```

The tool itself is pinned via the `tool` directive in `go.mod` (Go 1.24+);
`go tool oapi-codegen` resolves the version from there. No separate
`tools/tools.go` blank-import file.

`go generate ./...` produces `internal/abs/gen.go` containing:

- typed models for every schema (`Library`, `LibraryItem`, `BookMetadata`, `UpdateMediaRequest`, …)
- a `ClientWithResponses` exposing methods like `GetMe`, `ListLibraries`, `ListLibraryItems`, `SearchLibrary`, `UpdateItemMedia`, `SetItemCover`
- a `RequestEditorFn` hook used to attach `Authorization: Bearer …` per request

`internal/abs/client.go` wraps the generated client with our concerns:
constructing it with the right base URL, attaching the bearer editor,
adding a request/response logger that redacts the Authorization header,
and providing the multipart upload helper (multipart isn't ergonomic
through the generated client).

The generated file is committed (so consumers don't need `go generate`
on a fresh checkout). CI verifies it is in sync via
`go generate ./... && git diff --exit-code`.

When a future feature needs more of the ABS surface area, the workflow
is: **edit `audiobookshelf.openapi.yaml` first**, run `go generate`,
commit both. The spec stays the source of truth.

### Why not a libro.fm OpenAPI spec too?

libro.fm has no published API and the endpoints we use are
reverse-engineered. Trying to lock them into an OpenAPI contract would
imply a stability they don't have, and changes would whipsaw two files
instead of one. The libro.fm client stays hand-written and small.

## Phases

### Phase 0 — probe scripts (no Go)

**Deliverable:** `scripts/probe-*.sh` that exercise every endpoint we
plan to call, against real libro.fm and real ABS, using only `curl` and
`jq`. Each prints the response and exits non-zero on failure.

Already drafted in this branch; see [05-probe-scripts.md](05-probe-scripts.md).

**Checkpoint:** user runs the probes locally and confirms (or
files issues) that:
- libro.fm login works for their account
- libro.fm library lists their books
- libro.fm manifests return real URLs for at least one ISBN
- ABS API token authenticates against `/api/me` (proves Authelia bypass works)
- ABS library list, search, PATCH media, and cover upload all behave as documented

Only proceed to Phase 1 after this checkpoint passes. If anything
doesn't match the docs, the docs (not the code) are wrong — update
them first.

### Phase 1 — libro.fm client

**Deliverable:** `internal/librofm` package, fully typed, with
unit tests using `httptest.NewServer` to stub responses.

- `Client.Login(ctx) (token, error)` — uses cached token if present and non-empty, else POSTs `/oauth/token`. Caches result.
- `Client.Library(ctx) ([]Book, error)` — auto-paginates.
- `Client.M4BURL(ctx, isbn) (string, error)` — returns `("", ErrNoM4B)` on 404.
- `Client.MP3Manifest(ctx, isbn) (Manifest, error)`.
- `Client.AudiobookDetails(ctx, isbn) (Book, error)` — used to enrich library results that lack some fields.
- `Client.Download(ctx, url) (io.ReadCloser, error)` — bare GET that *doesn't* attach the bearer if the URL hostname isn't `libro.fm` (matches `DownloadClient.ts:73-78`).

Logging: every request emits `slog.Debug("librofm request", "method", ..., "path", ..., "status", ...)` with redacted Authorization.

**Checkpoint:** unit tests pass, plus a `go run ./cmd/librofm-sync probe-librofm` (hidden subcommand) hits real libro.fm and prints the library titles.

### Phase 2 — audiobookshelf client

**Deliverable:** `internal/abs` package, same test approach.

- `Client.Me(ctx) (User, error)` — auth probe.
- `Client.Libraries(ctx) ([]Library, error)`.
- `Client.LibraryItems(ctx, libraryID) ([]Item, error)` — paginates with `limit=200&minified=1` until exhausted.
- `Client.SearchLibrary(ctx, libraryID, query) ([]Item, error)`.
- `Client.Upload(ctx, libraryID, folderID, title, author, series, files []FileBlob) error`.
- `Client.DiscoverItem(ctx, libraryID, title, author) (itemID, error)` — polling helper with bounded backoff (1s, 2s, 4s, 8s, 16s, fail).
- `Client.UpdateMedia(ctx, itemID, metadata Metadata) error`.
- `Client.SetCoverFromURL(ctx, itemID, url string) error`.

**Checkpoint:** `go run ./cmd/librofm-sync probe-abs` (hidden subcommand) lists libraries and items from real ABS.

### Phase 3 — format adapters

**Deliverable:** `internal/format`.

- `m4b.Download(ctx, lf *librofm.Client, book librofm.Book, workDir string) (Result, error)` — tries M4B endpoint, returns `(Result{}, ErrFallback)` on 404 so the caller can switch to MP3.
- `mp3.Download(...)` — same signature. Fetches manifest, downloads each part, unzips into `workDir/<isbn>/`, ID3-tags each MP3 with title/artist/album/track-num/chapter-title/cover image.
- `id3.WriteTags(filePath string, tags Tags) error` — wraps `bogem/id3v2`. Cover bytes are attached as APIC frame.

**Result struct:**

```go
type Result struct {
    Files       []string // paths to upload (1 for M4B, N for MP3)
    SuggestedTitle string
    SuggestedAuthor string
    SuggestedSeries string
}
```

**Checkpoint:** `go run ./cmd/librofm-sync probe-download <isbn>` downloads a single ISBN to `./out/<isbn>/`. Manually inspect the resulting M4B/MP3 has correct tags and plays.

### Phase 4 — reconciler

**Deliverable:** `internal/reconcile`.

Algorithm from [ADR-005](03-architecture-decisions.md#adr-005--idempotency--partial-failure-recovery):

```go
func Run(ctx, lf *librofm.Client, abs *abs.Client, opts Opts) (Summary, error) {
    librofmBooks := lf.Library(ctx)              // []Book
    absItems     := abs.LibraryItems(ctx, lib)    // []Item

    byISBN := indexByISBN(absItems)
    byFuzz := indexByTitleAuthor(absItems)

    for _, book := range librofmBooks {
        switch state := classify(book, byISBN, byFuzz); state {
        case NotPresent:        downloadAndUpload(book) ; patch(...) ; cover(...)
        case PresentNoMetadata: patch(...) ; cover(...)
        case PresentSynced:     skip
        }
    }
}
```

Tests: table-driven, mock both clients with stub implementations.
Cover the partial-failure cases (upload OK, PATCH fails; PATCH OK, cover fails; book missing ISBN in libro.fm).

**Checkpoint:** end-to-end `--dry-run` against real services prints
the planned actions without touching anything.

### Phase 5 — CLI wire-up

`cmd/librofm-sync/main.go`:

- Parse flags + env (ADR-006).
- Construct clients with proper timeouts (60s default, 5min for downloads).
- Run reconciler.
- Emit summary: `synced=12 skipped=87 failed=1` and exit 0/1.

### Phase 6 — Polish & docs

- README rewrite: install, configure, Authelia snippet, cron example.
- `--help` text completeness.
- GitHub Actions: lint (golangci-lint), test, build for linux/amd64 and linux/arm64.
- Tag v0.1.0.

## Dependencies between phases

```
Phase 0 (probes)  ─┐
                   ├─► Phase 1 (libro.fm client)  ─┐
                   ├─► Phase 2 (ABS client)       ─┤
                                                   ├─► Phase 3 (formats)  ─► Phase 4 (reconciler)  ─► Phase 5 (CLI)  ─► Phase 6 (polish)
```

Phases 1 and 2 are independent and can be done in parallel.

## Testing strategy

- **Unit tests** for every package, using `httptest.NewServer` to stub HTTP responses. Target: 70%+ line coverage on `internal/`.
- **No mocks of file system** — use `t.TempDir()` and real files; downloads are small in tests.
- **No live integration tests in CI** (we don't want to hit libro.fm from CI). The probe scripts cover that role for humans.
- **Race detector** enabled in `go test -race`.
- **Golden files** for the PATCH-media JSON payload — small enough that a regression is obvious.

## Risks & mitigations

| Risk                                                       | Mitigation                                                       |
| ---------------------------------------------------------- | ---------------------------------------------------------------- |
| libro.fm changes API versions or removes endpoints         | Probes will fail loudly; `--extra-header` provides flexibility   |
| libro.fm rate-limits us                                    | Single-threaded downloads in v1; backoff on 429                  |
| ABS API key gets exposed in logs                           | Centralized redaction in `internal/logx`                         |
| Disk fills up from work-dir not being cleaned              | `defer os.RemoveAll(workDir)` per book, plus startup sweep       |
| Partial uploads (network drop mid-upload)                  | ABS's auto-scanner will pick up partial files; we re-PATCH on next run, but the file may be corrupt — log and require manual cleanup |
| User's libro.fm account has 2FA / hardware key             | Untested; fail fast with a clear error message and a docs link   |
| Concurrent runs (overlapping cron ticks)                   | Acquire a flock on `<cache-dir>/lock` at startup; exit if held   |

## Out-of-scope for v1

Explicitly deferred:
- Wishlist sync (libro.fm ↔ ABS collections / want-to-read).
- PDF extras download.
- Progress sync (listening position).
- Deletion sync (book removed from libro.fm → removed from ABS). Risk of data loss; not worth it.
- Multi-user (multiple libro.fm accounts → one ABS).
- Web UI / HTTP endpoint.

Each of these is a candidate for a future flag/subcommand.
